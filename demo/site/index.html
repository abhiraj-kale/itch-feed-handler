Every message.In order.Even when thenetwork isn’t.

Nasdaq publishes every order on the exchange as tiny binary messages over UDP, and UDP loses packets. The FH-50 reads those messages where they land without copying them, notices every missing packet from its sequence number, asks for it again, and rebuilds each stock’s order book exactly.

04

Functional block diagram

Two threads. The network thread owns the socket, the sequencing, the parser, and the books. Top-of-book changes cross to the strategy thread on a lock-free ring, so a slow strategy can never stall the feed.

1

Gap recovery

Each packet carries the sequence number of its first message. A packet from the future is parked, the missing range is requested from the retransmission server, and parked packets are released the moment the hole is filled. Duplicates and overlaps are trimmed message by message.

2

Zero-copy parsing

The parser walks 2-byte length prefixes in place and hands out views. A field is a memcpy plus a byte swap, which compiles to one load and a bswap.

3

Prefetch ahead

The order table is the one structure that does not fit in cache. The parser looks 8 messages ahead and prefetches the slot each upcoming execute, cancel, delete, or replace will touch.

4

Flat order table

Live orders sit inline in an open-addressing table: 24-byte records, linear probing, backward-shift deletion, so add and delete churn never leaves tombstones.

5

Strategy hand-off

When a symbol’s best bid or ask changes, a 32-byte update goes onto an SPSC ring. If the strategy falls behind, updates are counted and dropped instead of blocking the feed.
